skill

在 Claude Code Skills 官方文档 里，Skill 的定位其实非常明确：

Skill = 可自动触发的“能力包（capability package）”

它不是 prompt snippet，也不是 command alias，而是一套：

  • 触发条件（description）
  • 操作规范（SKILL.md）
  • 可执行脚本
  • 模板/参考资料
  • 工作流约束

真正难的不是“怎么写 Skill”，而是：

如何长期管理几十个 Skill，而不让 Claude 失控、污染上下文、互相冲突。

下面是目前社区里比较成熟的一套实践（Anthropic 官方 + 大团队经验 + 高频用户总结）。

一、先理解 Claude Code 的 Skill 加载机制（非常重要）

Claude Code 的 Skill 是：

1. metadata 预加载

启动时只加载：

  • name
  • description

不会加载完整内容。(Claude API Docs)

所以：

✅ 可以安装很多 Skill ❌ 不能写很长 description

2. 命中后才加载 SKILL.md

Claude 判断： “这个任务可能需要该 Skill”

才会读：

  • SKILL.md
  • scripts/
  • templates/
  • examples/

所以：

Skill 的核心是“可发现性（discoverability）”

不是写长 prompt。

二、Skill 管理最佳实践（最重要部分）

1. 按“能力边界”拆 Skill，而不是按技术栈

这是官方最强调的。(Claude API Docs)

❌ 错误拆法

frontend-skill
backend-skill
python-skill

问题：

  • 太大
  • 激活概率混乱
  • context 爆炸
  • Claude 不知道该用哪个

✅ 正确拆法

react-component-patterns
react-performance-audit
nextjs-app-router
prisma-migration-review
git-commit-writer
test-failure-debugger
api-contract-checker

原则：

一个 Skill 只解决一个“高频、重复、稳定”的问题。

2. CLAUDE.md 放“项目知识”

Skill 放“通用能力”

这是现在成熟团队最常见结构。(reddit.com)

CLAUDE.md 适合放

项目级上下文

# architecture

# service topology

# test commands

# deploy flow

# env vars

# coding conventions

即：

“这个项目是什么”

Skill 适合放

可复用 SOP

如何 review React 性能
如何生成 commit message
如何分析 flaky tests
如何 debug docker networking

即：

“遇到某类问题怎么办”

3. Skill 不要超过 300~800 行

虽然官方没写硬限制。

但大量实践证明：

超长 Skill 会显著降低执行稳定性。

原因：

  • Claude 会 selective attention
  • 后半段经常被忽略
  • instruction conflict 增加

推荐结构

SKILL.md
examples/
scripts/
templates/
reference/

把：

  • 示例
  • 长文档
  • API
  • cheatsheet

拆出去。

SKILL.md 只保留：

WHEN TO USE
WORKFLOW
RULES
CHECKLIST

4. description 比正文更重要

因为：

  • description 决定是否触发
  • SKILL.md 决定如何执行

好 description 示例

description: Review React components for unnecessary re-renders,
memoization issues, expensive hooks, and bundle size regressions.
Use when optimizing React performance or profiling UI lag.

坏 description

description: React helper

Claude 根本不知道什么时候触发。

5. Skill 要“强约束”

Skill 最怕：

“给建议”

而不是：

“定义流程”

❌ 差 Skill

Try to improve performance.

✅ 好 Skill

Workflow:
1. Run React profiler
2. Identify top render offenders
3. Check memoization
4. Check effect dependencies
5. Compare bundle diff
6. Produce markdown report

Claude 对 checklist/workflow 响应极好。

三、大团队的 Skill 分层（推荐）

这是目前比较先进的一种组织法。

Layer 1：基础工程 Skill

git-workflow
testing
debugging
code-review
commit-message

特点：

  • 全项目共享
  • 最稳定
  • 最常触发

Layer 2：技术栈 Skill

react-patterns
fastapi-patterns
postgres-optimization
redis-debugging

特点：

  • 技术相关
  • 可跨项目

Layer 3：业务 Skill

billing-domain-rules
analytics-event-schema
multi-tenant-safety

特点：

  • 项目私有
  • 放 project skills

目录：

.claude/skills/

四、推荐目录结构（成熟方案）

.claude/
├── CLAUDE.md
├── skills/
│   ├── react-performance/
│   │   ├── SKILL.md
│   │   ├── examples/
│   │   ├── scripts/
│   │   └── templates/
│   │
│   ├── test-debugger/
│   └── commit-writer/

个人通用：

~/.claude/skills/

项目专属：

project/.claude/skills/

官方也是这么推荐的。(Claude API Docs)

五、真正高级的实践（很多人不知道）

1. Skill ≠ Prompt

Skill 应该像“微型 Agent”

高级 Skill 一般包含：

scripts/

比如：

analyze.sh
run-tests.sh
generate-report.py

Claude 会自动调用。

这比纯 prompt 稳定很多。

2. Skill 要“可验证”

Anthropic 官方特别强调：

Claude 必须能验证自己的工作。(Claude)

所以 Skill 最好内置：

Verification:
- run tests
- compare snapshots
- check lint
- verify build

3. Skill 不要互相重叠

比如：

❌

react-best-practices
react-performance
frontend-review

三者 overlap 太大。

Claude 容易：

  • 同时加载
  • instruction 冲突
  • token 爆炸

4. 用“触发词”设计 Skill

Claude 的匹配很依赖语义。

所以 description 里应该出现：

Use when:
- flaky tests
- CI failures
- hydration mismatch
- rerender issues

而不是抽象词。

六、很多人踩的大坑

坑 1：把整个团队规范塞进一个 Skill

结果：

frontend-best-practices-v9-final-final

3000 行。

Claude 后半段完全不看。

坑 2：Skill 太泛化

code-helper
engineering-helper
assistant-helper

等于没写。

坑 3：把项目知识放个人 Skill

会导致：

  • skill 污染
  • 跨项目误触发
  • context 干扰

坑 4：Skill 太多

不是越多越好。

成熟团队一般：

常驻高质量 Skill

10~30 个

已经很多了。

七、我建议的最佳体系（个人/团队都适用）

推荐结构

全局（个人）

~/.claude/skills/

git-workflow
debugging
reviewer
test-runner
architecture-review

项目级

project/.claude/skills/

domain-rules
deploy-flow
db-migration-rules
api-contracts

CLAUDE.md

只保留：

commands
architecture
services
env
workflow

不要写 SOP。

八、一个高质量 Skill 模板（推荐）

---
name: react-performance-review
description: Review React rendering performance, memoization,
effect dependencies, and unnecessary rerenders.
Use when optimizing UI lag or profiling React apps.
---

# Purpose

Optimize React rendering performance.

# Workflow

1. Run profiler
2. Identify expensive renders
3. Check memoization
4. Analyze hooks
5. Compare bundle diff

# Verification

- run tests
- verify no regression
- compare render counts

# Output Format

- bottlenecks
- fixes
- estimated impact

九、最终结论（核心原则）

Claude Code Skill 管理，本质上就三句话：

1. Skill 要小

一个 Skill = 一个稳定能力

2. Skill 要强约束

workflow > advice

3. CLAUDE.md 管项目

Skill 管 SOP

这是目前最稳定的组织方式。(reddit.com)
