Spec

SillyTavern 的角色卡（Character Card）本质上是一段遵循特定 JSON 规范的元数据，通常直接嵌入在 PNG 头像图片中。这套规范从 V1 到 V3 的演进，核心逻辑是从“扁平化”走向“结构化”，并增加了对扩展功能的原生支持。

一、 各版本核心字段与示例

V1 版本（Legacy，已淘汰）

这是最原始的“酒馆”格式，结构极其简单，所有字段直接平铺在根级。它缺乏版本标识，现代 SillyTavern 会将其自动转换。 - 示例代码：

{
  "name": "亚瑟",
  "description": "圆桌骑士团的领袖，手持圣剑Excalibur。",
  "personality": "正直、勇敢、富有骑士精神",
  "scenario": "卡美洛城的王座厅",
  "first_mes": "*站起身，手按剑柄* 欢迎来到卡美洛，旅者。",
  "mes_example": "{{user}}: 你是谁？\n{{char}}: 我是亚瑟，不列颠的国王。"
}
  • 必填字段：仅包含 name, description, personality, scenario, first_mes, mes_example 这 6 个核心字段。

V2 版本（Current Standard）

目前最广泛使用的标准。它引入了 spec 版本标识，并将所有角色数据包裹在 data 对象内，新增了系统提示词、角色书等高级功能。 - 示例代码：

{
  "spec": "chara_card_v2",
  "spec_version": "2.0",
  "data": {
    "name": "亚瑟",
    "description": "不列颠的传奇国王，内心背负着王国的重担。",
    "personality": "正直但多疑，荣誉感极强",
    "scenario": "王国正面临内战危机",
    "first_mes": "*凝视着地图* 告诉我，你是敌是友？",
    "mes_example": "{{user}}: 我需要你的帮助\n{{char}}: *苦笑* 如今连国王也需要帮助。",
    "system_prompt": "始终以国王的口吻说话，避免现代词汇。",
    "creator_notes": "设定在《阿瓦隆的迷雾》时间线",
    "tags": ["骑士", "国王", "奇幻"],
    "alternate_greetings": ["*疲惫地坐在王座上* 又一位求见者..."],
    "extensions": {
      "talkativeness": 0.7
    }
  }
}
  • 关键新增：system_prompt（系统级指令）、creator_notes（作者备注）、alternate_greetings（多问候语）、character_book（角色书/世界书）。

V3 版本（Extended）

V3 在 V2 的基础上进一步扩展，主要变化在于 extensions 字段的标准化，并支持更复杂的元数据（如语义版本控制）。SillyTavern 内部通常将其归一化为 V2 处理。 - 示例代码：

{
  "spec": "chara_card_v3",
  "spec_version": "3.0",
  "data": {
    ... // 包含 V2 所有字段
    "extensions": {
      "depth_prompt": {
        "depth": 3,
        "prompt": "当对话深度达到3层时，触发此背景故事提示。"
      },
      "limerence": {
        "tools": ["memory_search", "web_search"]
      }
    }
  },
  "metadata": {
    "version": "1.0.0",
    "created_date": "2024-01-01"
  }
}
  • 关键差异：明确的 spec_v3 标识，以及更结构化的 extensions 和 metadata 层，为工具集成（如记忆、搜索）提供了官方规范。

二、 核心字段功能详解

无论版本如何，以下字段构成了角色卡的灵魂（按重要性排序）：

字段名 作用与编写技巧
name 角色名称。AI 不直接使用它生成文本，仅用于界面显示。
description （权重最高） 角色的“定义文档”。应包含外貌、性格、背景、说话风格。使用 {{char}} 和 {{user}} 作为占位符。
personality 性格摘要（如“傲娇、善良”）。在旧版中权重高，在 V2/V3 中常被合并到 description。
scenario 当前对话的背景设定（如“在图书馆偶遇”）。帮助 AI 理解开场情境。
first_mes 开场白。必须由 AI 发出，用于建立第一印象和对话节奏。
mes_example （教学权重高） 对话示例。严格遵循 用户: ...\n角色: ... 格式，教 AI 如何回应。
system_prompt （V2+）最高优先级的系统指令。用于设定 OOC 规则、输出格式限制等。
character_book （V2+）内置的世界观/知识库。当对话触发关键词时，自动插入相关 Lore 条目。

三、 V1 / V2 / V3 主要差异对比

维度 V1 (Legacy) V2 (Current) V3 (Extended)
结构 扁平 JSON，无嵌套 根级 spec + data 对象包裹 同 V2，增加 metadata
标识 无 spec 字段 "spec": "chara_card_v2" "spec": "chara_card_v3"
扩展性 无扩展机制 有 extensions 对象（SillyTavern 自定义） 标准化 extensions，支持工具链
角色书 ❌ 不支持 ✅ 支持 (character_book) ✅ 增强支持
系统指令 ❌ 无 system_prompt ✅ 有 system_prompt ✅ 同 V2
兼容性 自动转换 现代 SillyTavern 原生支持 通常归一化为 V2 处理

升级建议：目前制作新卡应直接使用 V2 格式。V3 格式更多是针对特定扩展插件（如 Limerence）或开发者工具链的进阶需求，对于普通用户而言，V2 的功能已经完全足够且兼容性最佳。

注意：SillyTavern 在保存角色卡时，会将 JSON 进行 Base64 编码并写入 PNG 图片的 chara (V1/V2) 或 ccv3 (V3) 文本块中，从而实现“图卡一体”。
